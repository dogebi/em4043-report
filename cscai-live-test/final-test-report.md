## 关键发现

- 敏感信息处理存在风险：客户报告最终文本强调了脱敏，但工具/中间输出曾显示原始敏感字段。建议将 Jira/MCP 原始响应在 UI 展示层也做脱敏，不能只在最终报告中脱敏。
- Jira 字段可用性不足：priority 字段在 Jira Search API 和 Issue Get API 返回中均不可见，导致 Leader/SM 统计无法完成优先级分布。
- 资产统计数据源未接入：当前知识库 assets/目录无法提供资产总数和分类，SM 资产统计只能输出缺口说明。
- 长对话稳定性较差：当前会话历史很长，Orca accessibility tree 被 1200 节点截断，页面滚动和发送坐标容易造成重复发送或结果不可见。
- 统计口径存在可疑点：SM 统计中出现 total=14 与逐条展开 13 条的差异，系统已提示需要从 Jira 前端按 created >= 09-01 核对。

## 建议

1. 把脱敏从最终文案扩展到工具结果展示、调试面板、报告生成前的中间状态。
2. 检查 Jira MCP 的字段权限或字段白名单，至少开放 priority、assignee、created、updated、status、asset/CMDB 关联字段。
3. 给统计类功能增加“数据不可用”标准输出模板，明确字段缺失、接口权限缺失和口径不一致。
4. 对当前聊天 UI 增加防重复发送保护，或在发送后禁用按钮直到请求状态稳定。
5. 对长对话增加消息锚点、最新回复定位或导出功能，方便验证最后一次测试结果。
